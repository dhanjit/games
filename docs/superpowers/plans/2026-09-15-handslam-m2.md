# handslam M2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fill the desk — six kids, elimination, and a match that ends with one hand standing, readable on a portrait phone.

**Architecture:** Unchanged from M1. `handslam/rules.js` stays the pure, DOM-free simulation; `handslam/game.js` reads the world and advances it only via `step()`. The bait rule was written general over player count in M1 and already runs correctly at six — **M2 is mostly renderer and verification work, not new rules.** Resist adding simulation code: if a task seems to need a new rule, check whether the existing one already covers it.

**Tech Stack:** Vanilla ES modules, `<canvas>` 2D, `node --test` with `node:test` + `node:assert`. No build step, no bundler, no `package.json`.

**Spec:** `docs/superpowers/specs/2026-09-14-handslam-design.md` · **Issue:** #66 under #63 · **Builds on:** #64 (M1)

## Global Constraints

- **No build step, no bundler, no `package.json`.** Pure static files, modern ES.
- **`rules.js` must import cleanly in Node** — no `window`, `document`, `performance`, `requestAnimationFrame`, `Math.random`. Randomness comes only from the seeded `world.rng`, and seeded bot matches must replay identically (there is a test).
- **`game.js` never mutates the world** except by calling `step()`.
- **Portrait phone is the primary target**, verified at 375×812. The page never scrolls or zooms.
- Units are seconds; the hand's retreat is a scalar `0 → 1`; all pixel scaling lives in `game.js`.
- **Every persona must satisfy `spookAt > T.windTime + T.loadMin`** — there is a test enforcing it. `nerveFloor` must exceed `T.slideCost`.
- ES modules everywhere. Tests are `.mjs`. Test command: `node --test "handslam/test/*.test.mjs"` — the quoted glob is required; a bare directory argument fails on Windows Node 24.
- Bots stay on the single `kid` persona. The named six-character roster is M4.

## What is already true, measured before this plan was written

Running `rules.js` at `nBots: 5`, 60 seeded bot-only matches, 300 s guard:

- **100% of matches end.** Median 30.6 s, p10 19.8 s, p90 45.2 s.
- Share of `goesDown` by seat: 10.3 / 17.6 / 19.2 / 19.0 / 16.4 / 17.5 % (even would be 16.7%). Seat 0 reads low only because every match *starts* with seat 0 down and that first turn is not a `goesDown` event.
- Average entries per resolved bait: 2.49 of a possible 5. Ties at the top: 18.2%.

So the simulation side of M2 largely works already. Two findings from that run are recorded on issue #66 and are **deliberately not fixed here** — `passive` being the dominant way to go down, and starting-down being a measurable disadvantage. Task 3 re-measures both so the decision is made on current numbers.

```js
test('a world defaults to six kids, one of them down', () => {
  const w = createWorld({ seed: 1 });
  assert.strictEqual(w.players.length, 6);
  assert.strictEqual(w.n, 6);
  assert.strictEqual(w.players.filter(p => p.isHuman).length, 1);
  assert.strictEqual(w.down, 0);
});

test('a bait with five attackers ranks every entry and sends down exactly one', () => {
  const w = createWorld({ humans: 6, nBots: 0, seed: 1, down: 0, hp: 99 });
  // 1 and 2 load and will abort; 3 loads and freezes; 4 and 5 never wind.
  advance(w, T.windTime + T.loadMin + 0.01, { 1: { hold: true }, 2: { hold: true }, 3: { hold: true } });
  advance(w, T.slideTime + 0.02, { 0: { hold: true }, 1: { hold: true }, 2: { hold: true }, 3: { hold: true } });
  advance(w, 0.06, { 0: { hold: true }, 1: { hold: false }, 2: { hold: true }, 3: { hold: true } });  // 1 aborts early
  const evs = advance(w, T.baitWindow + T.dropTime + 0.1,
    { 0: { hold: true }, 2: { hold: false }, 3: { hold: true } });                                     // 2 aborts later
  const res = evs.find(e => e.type === 'baitResolve');
  assert.ok(res, 'the bait must resolve');
  assert.ok(res.entries.length >= 4, `expected most fists entered, got ${res.entries.length}`);
  assert.strictEqual(evs.filter(e => e.type === 'goesDown').length, 1, 'exactly one kid goes down');
  assert.strictEqual(w.down, res.loser);
  assert.notStrictEqual(res.loser, 1, 'the earliest aborter must not be the one who pays');
});

test('entries are ordered latest-first, so the loser is the last to resolve', () => {
  const w = createWorld({ humans: 6, nBots: 0, seed: 2, down: 0, hp: 99 });
  advance(w, T.windTime + T.loadMin + 0.01, { 1: { hold: true }, 2: { hold: true } });
  advance(w, T.slideTime + 0.02, { 0: { hold: true }, 1: { hold: true }, 2: { hold: true } });
  const evs = advance(w, T.baitWindow + T.dropTime + 0.1, { 0: { hold: true }, 1: { hold: false }, 2: { hold: false } });
  const res = evs.find(e => e.type === 'baitResolve');
  for (let i = 1; i < res.entries.length; i++) {
    assert.ok(res.entries[i - 1].t >= res.entries[i].t, 'entries must be sorted latest-first');
  }
  assert.strictEqual(res.loser, res.entries[0].id);
});

test('an eliminated kid takes no part — no entry, no strike, never sent down', () => {
  const w = createWorld({ humans: 6, nBots: 0, seed: 3, down: 0, hp: 99 });
  w.players[4].out = true;
  advance(w, T.windTime + T.loadMin + 0.01, { 1: { hold: true }, 4: { hold: true } });
  assert.strictEqual(w.players[4].fist.state, 'ready', 'an out kid cannot wind');
  advance(w, T.slideTime + 0.02, { 0: { hold: true }, 1: { hold: true } });
  const evs = advance(w, T.baitWindow + T.dropTime + 0.1, { 0: { hold: true }, 1: { hold: false } });
  const res = evs.find(e => e.type === 'baitResolve');
  assert.ok(!res.entries.some(e => e.id === 4), 'an out kid must not get an entry');
  assert.notStrictEqual(w.down, 4);
});

test('the palm never lands on an eliminated kid, even when seats are sparse', () => {
  const w = createWorld({ humans: 0, nBots: 6, seed: 11, down: 0 });
  let guard = 0;
  while (!w.over && guard++ < 120 * 300) {
    step(w, 1 / 120, {});
    assert.ok(!w.players[w.down].out, `the kid who is down must be alive (t=${w.t.toFixed(2)})`);
  }
  assert.strictEqual(w.over, true);
});

test('a six-player bot match reaches exactly one winner', () => {
  const w = createWorld({ humans: 0, nBots: 6, seed: 12, down: 0 });
  let guard = 0;
  while (!w.over && guard++ < 120 * 300) step(w, 1 / 120, {});
  assert.strictEqual(w.over, true, 'a six-player match must terminate');
  const alive = w.players.filter(p => !p.out);
  assert.strictEqual(alive.length, 1);
  assert.strictEqual(w.winner, alive[0].id);
});
```

### Task 2: Six on a phone screen

**Files:**
- Modify: `handslam/game.js`

**Interfaces:**
- Consumes: `seatGeom`, `drawHand`, `drawFist`, `drawHud`, `bakeDesk`, `render` from M1.
- Produces: a layout that holds six seats at 375×812 with nothing clipped. No API change.

**The specific problem to solve.** At 375×812 the desk radius is `min(375 × 0.44, 812 × 0.34)` = 165, so the ellipse spans x = 22 → 352 with ~22px of margin. `drawHud` places each label at **1.16× the radius from centre**, which for the 3-o'clock seat is x ≈ 379 — off the right edge of a 375px screen. With two seats (top and bottom) this never showed; with six it clips immediately.

Fix the layout so that at 375×812, with six seats:

- **No label, HP pip or nerve bar is clipped or overlapping another.** The simplest approach is to move each kid's label *inside* the desk rim rather than outside it — the desk is large and mostly empty, and the arms only occupy a radial band. Shrinking the desk instead is allowed, but it must not make the hand, wrist and strike spot harder to read, because those three are the game.
- **Who is down must be obvious at a glance** — more than a text colour. Someone glancing at the screen should locate the flat hand instantly.
- **Every kid's HP must be readable**, including at 1 HP. Pips are fine; if six names will not fit, prefer shortening or dropping names over dropping HP — HP is game state, names are flavour.
- **The defender's nerve bar stays legible.** It currently sits at the defender's own desk edge.
- Keep the derived wrist geometry exactly as it is (`retreatPx = HAND_RX / T.handGrace`). If you change `HAND_RX`, the wrist band follows automatically — verify it still does.

## Self-Review

**Spec coverage.** Issue #66's done-when list maps as: six seats rendering and playing at 375×812 (Task 2), a match reaching a single winner across seeded runs (Tasks 1 and 3), match length and who-goes-down measured and recorded (Task 3 Step 4), eliminated kids inert (Task 1 tests plus Task 3 visuals), and tests covering a multi-entry bait and an elimination (Task 1).

**Deliberately not here:** the six-character roster and signature moves (M4), `sim/run.mjs` as a committed harness (M3 — Task 3's measurement script is a throwaway and must stay out of the repo), audio, PWA, hub card (M5).

**Two open decisions this plan records but does not make**, both from measurements on issue #66:

1. `passive` is the most common way to go down at six seats, which means the anti-turtle backstop fires more often than the abort-reaction test the design rests on.
2. Starting down is a measurable disadvantage, and the human is always seat 0.

Both change designed behaviour that was explicitly approved, so they are the user's call, and M3's balance pass is the natural place. Task 3 Step 4 re-measures both so the decision is made on current numbers rather than these.

**One risk worth naming.** Task 2 is the only task here with real design judgement in it, and it has no unit test — a canvas is verified in a browser at a real size. Its steps demand numbers (label positions against the viewport) rather than impressions, for exactly that reason.
